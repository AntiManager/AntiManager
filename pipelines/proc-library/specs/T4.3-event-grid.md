# T4.3 — Event grid: derivation spec

Status: frozen · Phase 4 (T4.artifacts, sub-plan 04) · English (service doc)

Canonical source: umbrella `1791810263662-artifact-chain-ktk-priority-grid.md`
§5 (grid table contract, horizon map, owner reassignment, token rules) and §6
(shared execution rules). This spec makes the derivation of the single event-grid
artifact reproducible: from the client ФРПС grid (347 lines, 11 sections) to the
unified `library/artifacts/Сетка_регулярных_событий.md`.

Format contract (frontmatter, heading, exact table header, cell vocabularies)
lives in `specs/T4.9-artifact-format.md`; the role register lives in
`specs/T4.0-role-archetypes.md` + `role_registry.json`. This spec adds only the
**derivation rules**.

## 1. Purpose and shape

One file, one section per source section, in source order:
`Принципы → Ежедневные Tier 1–3 → Еженедельные Tier 4 → Ежемесячные →
Квартальные → Годовые → Сводная → Регламенты → Шаблоны → Календарь → Гемба`.

Only the five **cadence sections** (§2–§6) carry the contract grid table; the
remaining sections are ported token-free prose/tables and are deliberately NOT
parsed (T4.9 §6). Ported sections therefore **keep the source's raw role titles
and unexpanded shorthand codes** (e.g. §7 `QUAL-07-02, -03`, §9/§11 client role
names); only §2–§6 are canonicalised. The file answers *what regular management
events exist, who owns them, and on what planning horizon they run* — every
cadence event tied to process codes so it is traceable (H7).

## 2. Column schema (source → unified)

Cadence sections carry the exact literal header from T4.9 §4:

| Column | Rule |
|---|---|
| `Триггер/Период` | source trigger/day/decade/period (§2–§3 keep the trigger; §4–§6 the period) |
| `Событие` | event name, de-identified (§6) |
| `Длительность` | source duration, `–` when absent |
| `Владелец` | exactly one canonical role, rendered `Имя (КОД)` with the **short** display name — the registry's trailing domain qualifier (e.g. `(техслужба)`) is dropped so the cell never shows double parentheses (§4) |
| `Участники` | canonical role codes, comma-separated, `–` when none (§5) |
| `Повестка` | source agenda (§2–§3); the other cadences have no agenda column → `–` |
| `Вход` | source input |
| `Выход` | source output |
| `Процессы` | ≥1 valid library process code (§7) |
| `Горизонт` | section cadence, §3 |

## 3. Horizon map (H3, H4)

`Горизонт ∈ {shift, day, week, month, quarter, year, event}`. The value is
section-consistent:

- §2 daily → `shift` for shift-level events (Tier 1, gemba/обход, смена-summary,
  входной контроль) and `day` for day-level events (Tier 2–3, суточный отчёт);
- §3 weekly → `week`; §4 monthly → `month`; §5 quarterly → `quarter`;
  §6 yearly → `year`.

Every row carries a non-empty horizon inside the section's allowed set (the
checker maps a section heading to `daily→{shift,day}`, `weekly→{week}`,
`monthly→{month}`, `quarterly→{quarter}`, `yearly→{year}`).

## 4. Owner reassignment (§5 event owner map)

The source `Владелец` free-text is reduced to exactly **one** canonical code.
`roles_for_string` (registry owner synonyms + fold map + event-owner map) is
tried first and **stays authoritative**: a label the registry already resolves
keeps the registry's primary code (e.g. `Диспетчер / Учётчик` resolves via the
event-owner map to РП). Only a label with no registry match falls through to an
explicit override:

| Source owner label | Code |
|---|---|
| `Специалист по развитию ПС` | ГТ (development of the production system folds into ГТ) |

The same fallback is applied to `Участники` fragments (§5), so a grid-only label
maps to the same code in both columns.

A multi-role cell (e.g. `Руководитель производства/Руководитель ПС`) resolves
to its **first/primary** role. When the cell still matches no role it is dropped
to `—` (a worker may not own an event, T4.0).

**Registry addition.** The canonical display names `Руководитель качества` (РК)
and `Руководитель склада` (РС) are added to `owner_synonyms` so an owner cell
written as `Имя (КОД)` resolves back to its code (makes W2 meaningful). This is
mirrored in `specs/T4.0`.

## 5. Participant reassignment

A `Участники` cell is split on `,`, `/`, `;` and parentheses; each fragment is
mapped through `roles_for_string`; bare register codes (`РП`, `ПЭО`-folded) are
accepted directly. A fragment with no registry match falls back to the owner
override (§4), so a grid-only label maps to the same code in both columns.
Worker fragments (`Оператор`, `Лаборант`, бригады, «команда улучшений»,
«владельцы процессов») map to nothing and are dropped (T4.0: workers are not
owners but may appear as folded participants, e.g. `Инженер по качеству → РК`,
`Диспетчер → РП/НЦ`). Fragments are matched by registry **singular** synonyms,
so a plural form with no synonym (e.g. `Начальники цехов`) currently maps to
nothing — a known limitation. The surviving codes are de-duplicated; an empty
result renders as `–`.

## 6. Token rules (H6)

The stop-word / identity list of umbrella §5 applies. The derivation reuses the
priority-matrix substitutions (`author_priority_matrix.CLEAN`, case-aware) and
adds grid-specific ones:

- `УПЛ` → «вышестоящий уровень управления» / «установленная форма»;
- `УСИС` → «орган по сертификации»; `ЦСМ` → «метрологическая служба»
  (`по графику ЦСМ` → `по графику поверки`);
- `«Регламент 8.x»` → «регламент 8.x» — H6 flags only the **client wording**
  (the capitalised phrase); the number is kept so §10 «Привязка к регламентам»
  stays traceable to the §8 subsections. A bare `8.x` is never stripped: it is
  the artifact's own §8 subsection number (`### 8.1. …`) and stripping it would
  shatter headings into `### .`;
- the method block referencing the client ПС ПП guide is replaced by a neutral
  TDM/гемба note; the footer cross-ref (`Proc_lib.md`) and the hard revision date
  (`01.07.2027`) are removed.

## 7. Code-traceability rule (H7)

Every grid row references ≥1 code that resolves to a library node (H2). Source
code shorthands (`STRAT-01-01, -02, -03`) are expanded to full codes
(`STRAT-01-02`, `STRAT-01-03`). A row whose codes all fail to resolve is dropped
(gaps = 0). Codes are matched literally, case-sensitive.

## 8. Verification

- `python pipelines/proc-library/check_artifacts.py "<vault>"` → `OK` (H1a, H2,
  H3, H4, H6, H7 for the grid).
- `... --cross` → no `H*`; `W2` clean (each owner is a library Владелец/Исполнитель
  of a row code) or explicitly signed off.
- `python pipelines/proc-library/token_scan.py "<vault>\library\artifacts"` →
  identity tokens `0`.
- Encoding guard clean.
- Derivation tool: `pipelines/proc-library/author_event_grid.py`
  (`--analyze` / `--emit <vault>`), reproducible from the source grid.
