# T4.0 — Canonical role register (artifacts)

Status: frozen · Phase 4 (T4.artifacts) · English (service doc)

Canonical source: umbrella `1791810263662-artifact-chain-ktk-priority-grid.md` §4.
Machine-readable twin: `pipelines/proc-library/role_registry.json` (loaded by
`check_artifacts.py`). This spec documents the register; the JSON is the single
runtime source — never duplicate the list a third time.

## Purpose

The unified library carries **free-text owner strings** (`**Владелец:**`), many
of them multi-valued and inconsistent (`"Начальник участка / Начальник смены"`,
`"Главный энергетик (совместно с главным механиком)"`). The three artifacts
(КТК, priority matrix, event grid) must speak ONE canonical role language so that
role sets are comparable across documents (invariant H1) and cross-document
claims resolve (W2). This spec freezes that language: **10 role codes**.

Codes are matched **literally, case-sensitive** (`ГД`, `РП`, …). Names are for
display only; the code is the key.

## Matching rule (owner string → role code)

`role_for_string(s)` splits `s` on `/`, `;`, `,` and parentheses, then returns the
first role whose synonym is a case-insensitive sub-string of the whole string.
Synonyms are deliberately ordered so a longer, more specific label wins before a
generic one. A string that matches no role maps to **no code** (it is a worker or
an unmapped participant) — artifacts must not invent a role for it (drop it, per
umbrella §5 «Event owner map»).

## Fold map (source actors → role code)

Folding is **lossy by design**; each folded artifact keeps a short token-free
note so the rationale survives. Grid participants and КТК «Участник/Косвенно»
claims are re-evaluated through this map.

|--------------|----------|
| ПЭО / Экономист (планово-экономическая служба) | РП, ГД |
| ИПП / Инженер по подготовке производства / Инженер по планированию | РП |
| РПС | ГТ |

## Not owners (workers / members — never a role heading, never a grid owner)

`Оператор`, `Ремонтный персонал`, `Учётчик`, `Кладовщик`, `Комплектовщик`,
`Водитель`, `Лаборант`, `Диспетчер`, `Инженер по качеству`, `Руководитель
проекта`, аудиторские/рабочие/экспертные группы.

Two of these are legitimate operation **executors** in the library and may appear
as folded **participants** (Инженер по качеству → РК, Диспетчер → РП/НЦ), but
none may be a role heading or an owner of an artifact row.

## Removal list (must never appear in artifacts)

- Holding/client tokens: `УК`, `ТД`/`Торговый дом`, `давальческая схема`, `ПУ`,
  `ПС ПП`, `ФРПС`, `СГИ`, `СГМ`, `УПЛ`, `УСИС`, `ЦСМ`, `Росприроднадзор`, `2-ТП`.
- Source refs: `REG-<n>`, `Proc_lib*.md`, cross-refs to
  `Приоритеты_руководителей.md` / `Proc_lib_KU.md` / `Proc_lib_BUDG.md`,
  `Power BI`, `«Регламент 8.x»`.
- Identity: person names, plant codes, legal entities, hard-coded dates
  (`01.07.2027`), hard numeric targets (`>10%`, `≤±5%`, `≥95%`, `100 тыс. руб`) —
  drop or mark `ориентир`.

Kept vocabulary (not tokens): `Tier 1–4`, `R/Y/G`, кайдзен, SMED, TPM, VSM, 5S,
A3, SPC, TWI, OEE/OPE, MTBF/MTTR, PDCA, гемба, Obeya, kanban, ABC/XYZ; verified
process codes; the 10 role codes; Entity-State tokens.
