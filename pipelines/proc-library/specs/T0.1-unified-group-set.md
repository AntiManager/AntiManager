# T0.1 — Unified group set (scope, seams, no duplicate codes)

Status: draft · Phase 0 · English (service doc)

## Purpose

Merge the groups of the source libraries into ONE top-level set for the SME
closed loop, exclude holding layers, and resolve seam overlaps with an explicit
process owner. Output is the authoritative `GROUP` list of the template.

Sources: `Proc_lib.md`, `Proc_lib_INF.md`, `Proc_lib_LOG.md`,
`Proc_lib_SLA_SL_PU.md`, `Proc_lib_Изменения_ТП.md`, `Proc_lib_BUDG.md`,
`Proc_lib_PU_proc.md`, `Proc_lib_KU.md` (all under
`Proc_library/library/processes/`).

## Decision 1 — scope boundary

Order of the SME loop is fixed by plan §3: **requisition→purchase→goods receipt**
and **order→shipment→settlement** are INSIDE the loop; external boundary is the
supplier (goods receipt) and the buyer (shipment/payment). Budget/finance is a
**thin interface**, not a process layer.

## Decision 2 — seam resolution (explicit owner)

Plan T0.1 flags overlaps MNT↔INF, PLAN↔INF-budget, LOG↔PLAN-stocks. Resolved:

1. **MNT ↔ INF ↔ SL_MNT (equipment maintenance).** The shared `ENTITY-STATE`
   `Оборудование` carries `assetClass ∈ {technological, infrastructure,
   logistics-fleet}`. Owner by class:
   - `technological` → **MNT** (ТОиР технологического оборудования);
   - `infrastructure` → **INF** (здания, сети, энергия, ГПМ, компрессоры,
     водоснабжение, газ; `INF-14` «Эксплуатация и ТО инженерных систем»);
   - `logistics-fleet` → **SL_MNT** (ТС, погрузчики, краны логистики).
   Cross-class influence is modelled by flow links, never by duplicate operations.

2. **PLAN ↔ INF-budget ↔ MNT-budget.** `INF-10` (Бюджетирование и экономика
   ТОиР) and `MNT-02` (Планирование ресурсов БТЗ/БИЗ/ФОТ) are the same function
   for two asset classes. Both are marked **`interface: finance`** (thin budget
   interface, out of the loop). No full budget process is built.

3. **PLAN-03 ↔ SL_PLAN-01 ↔ SL_LOG-01 (inventory).** Split by layer:
   - **PLAN-03** owns inventory **norms** (normative layer, strategic);
   - **SL_PLAN-01** owns operational replenishment / order point;
   - **SL_LOG-01** owns physical storage and accounting.
   Flow: `PLAN-03` norm → `SL_PLAN-01` order proposal → `SL_LOG-01` receipt.

4. **`SL_*` vs main-group name collision.** `SL_QUAL`≠`QUAL`, `SL_MNT`≠`MNT`,
   `SL_HRP`≠`HRP`, `SL_EMG`≠`EMG`, `SL_ANL`≠`ANLZ`. **Prefix `SL_` is kept
   verbatim in codes** — never stripped during merge. `SL_*` are
   logistics-domain specializations with distinct owners; they interoperate via
   typed I/O, not by merging operations. (Stripping the prefix is exactly the
   naive merge that would create duplicate codes flagged by validator §7.9.)

5. **Duplicate `ENG` group** (`Proc_lib.md` ENG-01 vs `Proc_lib_Изменения_ТП.md`
   ENG-04). Same group → ONE `library/ENG.md`. Codes do not collide
   (ENG-01 ≠ ENG-04). Owner unified to **Гл. технолог** (source lists НПУ —
   holding role, out of SME scope).

6. **`SLA` group** (production↔logistics interaction, `Proc_lib_SLA_SL_PU.md`).
   Kept as group `SLA`, domain `coordination` — it is the seam process set
   between production and logistics inside the loop.

## Decision 3 — code gaps (recorded, not invented)

- `SL_QUAL-05` is absent (sequence 01,02,03,04,06).
- `KU-02` is absent.
- `DIG` group contains `E2E-01/E2E-02` (wrong prefix) — out of scope anyway.

Gaps are recorded as data defects. Codes are **not renumbered** in Phase 0;
renumbering (if any) happens only after confirmation, and never silently.

## Decision 4 — technology externalization precedent

`MFG-04…25` are already externalized to `library/processes/technologies/*.md`
(SOP per technology). **Keep this pattern**: `MFG-01…03` stay inline as the
generic production process; `MFG-04…25` remain `PROCESS` nodes that reference an
external `sopRef`. T1.1 applies the same pattern to every split group.

## Verification

- "group → processes → owner" table above: **no duplicate codes** across the 21
  in-scope groups (main + INF + SL_* + SLA).
- Every seam (1–3) and the collisions (4–5) name one explicit owner.
- Out-of-scope list is closed and enumerated (no partial holding leakage).

## T1.5 — freeze status (2026-10-11, user decision)

Phase 1 is **frozen at 20 groups** (subprocess-level v1). Decision 1 listed
`SLA` and `ENG-04` as in scope; the freeze decision **supersedes** that for these
two (recorded, not silent):

- **`SLA`** (`Proc_lib_SLA_SL_PU.md`) — left out of the template. In-library trace
  is only annotation comments embedded in `MFG.md` / `SL_LOG.md`.
- **`ENG-04`** (`Proc_lib_Изменения_ТП.md`) — left out. Its machinery
  (НПУ / ОПЭ / ОРТ / ДТР, консилиум, multi-plant «заводы-заявители») is
  **holding-grade** and conflicts with plan §3 and T5.3 «no holding layers».

Frozen baseline: **20 groups / 79 processes / 238 subprocesses / 995 operations**;
0 errors at LIBRARY/GROUP/PROCESS/SUBPROCESS; APQC 79/79; identity-token scan 0.
Record: `.kilo/process-engine/freeze_v1_subprocess.json`. The T0.1 in-scope group
set for the frozen template is therefore the 20 groups in the `library/` index
(the T1.6 list above), not the 21 of Decision 1.
