# T0.2 — APQC PCF crosswalk

Status: agreed · Phase 0 · English (service doc)

## Purpose

Attach APQC PCF as a **crosswalk attribute** while the functional groups stay the
primary taxonomy (plan §2.5/§8.3 — reconfirmed by the user). No re-anchoring, no
code renaming.

Source of PCF codes: `Personal Vault/Archive/K014749_APQC Process Classification
Framework (PCF) - Cross-Industry - Excel Version 7.4.xlsx` (and `_ru`) — **v7.4**.

## Decision 1 — attribute model

- **`GROUP.apqcArea`** — one APQC **L1 category** anchor (e.g. `"4.0"`).
- **`PROCESS.apqc`** — list of APQC **L3 process** codes (many-to-many; the
  first entry is the *primary* reference). Rendered as an attribute
  `- **APQC:** 4.3.3` (T0.7).
- **`SUBPROCESS`** is not crosswalked individually; it inherits the process's
  primary L3 and may add an L4 activity code in `metadata`.
- **`OPERATION`** is not crosswalked (L5 task granularity is out of scope).

### Level mapping (explicit; corrects plan §T0.2 shorthand)

| Spiral A level | APQC PCF level |
|----------------|----------------|
| LIBRARY | — (whole PCF) |
| GROUP | L1 category / L2 process group (anchor) |
| PROCESS | **L3 process** (primary crosswalk unit) |
| SUBPROCESS | L4 activity (optional) |
| OPERATION | L5 task (not mapped) |

> Plan T0.2 wrote "L1↔GROUP, L2↔PROCESS, L3↔SUBPROCESS…". APQC has 5 levels
> (L1 category → L5 task) and its L2 is a *process group*, so anchoring our
> `PROCESS` at **L3** is the correct, unambiguous crosswalk unit. Recorded here
> as a deliberate correction, not silent drift.

## Decision 2 — many-to-many rule

- One our-process may reference several APQC L3 codes (e.g. `MFG-01`
  ≥ `4.3.2`, `4.3.3`).
- One APQC L3 code may be referenced by several our-processes across groups
  (e.g. `4.1` planning appears in `PLAN-*` and `SL_PLAN-*`).
- The **first** code is primary; the validator checks presence, not cardinality.

## Verification

- Convention is explicit: `apqcArea` on every GROUP, `apqc` on every PROCESS.
- Validation rule (engine + T1.3): **100 % of PROCESS nodes carry ≥1 `apqc`
  code**; a PROCESS without `apqc` fails.
- No re-anchoring: functional group codes (`STRAT-01`, `MFG-03`, …) are
  unchanged; APQC is additive.
