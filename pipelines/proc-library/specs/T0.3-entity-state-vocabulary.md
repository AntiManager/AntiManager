# T0.3 — `Entity-State` vocabulary

Status: draft · **version 0.3** · Phase 0 · English (service doc)

## Purpose

Extend the ontology §2 base type list into the controlled vocabulary that every
operation input/output must reference (plan §3: "All operation inputs/outputs
are taxonomy references, not free text"). Finalise the information-entity and
infrastructure-entity conventions.

Ontology base list (§2): `Сырьё, Материал, Полуфабрикат, ГотоваяПродукция,
Отходы, Документ, Заявка, Протокол, Отчёт, План, Бюджет, Партия, Заказ,
Кандидат, Сотрудник, Вакансия, Комплект`.

## Decision 1 — three kinds

Every `Entity-State` type belongs to exactly one **kind** (ontology axiom
"each entity has exactly one current type"; kind is the top split):

- `material` — physical substance/goods (ontology §15 → Spiral B
  `resources.type='material'`).
- `information` — data/document/record (ontology §15 → Spiral B
  `resources.type='infrastructure'`, i.e. Spiral B has no separate table yet).
- `resource` — durable organizational asset used across flows (equipment,
  buildings, people, transport). *New kind needed for infrastructure/inventory
  completeness; maps to Spiral B `resources` with a dedicated `type`.*

> Convention fixed here: **information entities are their own kind**
> (`information`), NOT folded into `resource`. Infrastructure assets are
> `resource`. The Spiral-B mapping is an implementation detail (both land in
> `resources` today) and does not force the source vocabulary.

## Decision 2 — inheritance & compatibility

- Types form a tree via `parent`. Root types have `parent: null`.
- **Substitution rule (validator §7.2):** a value of subtype may fill a slot
  declared as its supertype (подтип → надтип). The reverse is invalid.
- A state qualifier is optional: reference syntax `Type` or `Type@State`
  (e.g. `Заявка@Согласована`). The qualifier does not change the type.
- **Versioning:** this vocabulary is versioned (`version` above). A library file
  pins the vocabulary version it was validated against (`vocabulary: 0.1`).

## Extension rule

New types are added by appending to the `types` array (never renumbering) and
bumping `version` per semver: additive type = minor, rename/removal = major.
Any file referencing a removed type becomes invalid (validator §7.1).

## v0.2 — Planning & logistics additions (T2.1, 2026-10-11)

Additive (minor) bump for the Phase-2 pilot vertical **Planning** (`PLAN` +
`SL_PLAN`). New `information` entities the planning operations exchange:

- Order intake / register: `ПроизводственныйЗаказ`, `РеестрЗаказов`.
- Demand: `ПланПроизводства`, `ПотребностьВРесурсах`.
- Requisitions: `ЗаявкаНаЗакуп`, `ЗаявкаНаПеревозку`, `ЗаявкаНаОбучение`,
  `ЗаявкаНаПересмотрНормативов`.
- Execution docs: `СменносуточноеЗадание`, `ГрафикПроизводства`,
  `РапортПроизводства`, `Сводка`, `ОтчётОбОтклонениях`, `ДанныеОперативногоУчёта`,
  `МатериальныйБаланс`.
- Inventory norms: `НормативЗапаса` (+ `ТочкаЗаказа`, `СтраховойЗапас`),
  `ПараметрыЗапасов`.
- Logistics: `КлассификацияABCXYZ`, `ЗаданиеНаПеревозку`, `ДоговорЗаявка`,
  `ТаймСлот`, `ЛогистическиеОграничения`, `СвободнаяЁмкостьСклада`,
  `ЗоныХранения`, `РекомендацияПоЗапасам`, `ПереченьНеликвидов`,
  `ПереченьКритическихЗИП`, `УсловияПоставки`, `Накладная`.
- One `resource`: `Подрядчик`.

Boundary states use qualifiers on existing types (e.g. `ПроизводственныйЗаказ`
produced by an external-input **sensor**; `Отчёт@Утверждён` consumed by an
external-output **actor**). See `specs/T2.1-planning-domain-boundaries.md`.

## v0.3 — production-core additions (T2.6, 2026-10-11)

Additive (minor) bump for Phase-2 replication to the **production core**
(`MFG`). New entities the manufacturing operations exchange:

- `Запас` (`material`) — stock of material/goods at a work centre or store
  (`Запас@РабочееМесто`), a state of a `Материал`.
- `Этикетка` (`material`) — marking label applied to packed product.
- `Разрешение` (`information`) — permission to release/use an entity
  (e.g. `Разрешение@НаИспользованиеСырья` from quality control).
- `АктСдачиПриёмки` (`information`) — hand-over / acceptance document for
  finished goods (`АктСдачиПриёмки@Подписан`).

Manufacturing execution cadence uses existing qualifiers (`Оборудование@ВРежиме`,
`ГотоваяПродукция@Упакована`, `СменносуточноеЗадание@Доведено`,
`РапортПроизводства`, `ТехнологическаяКарта`, `Чертёж`, `СОП`, `Тара`,
`Оснастка`, `Инструмент`, `Накладная`). Boundary/shared-entity conventions for
the production core: `specs/T2.6-domain-replication.md`.

## Verification

- The vocabulary is versioned (`0.1`) and machine-readable (JSON block above).
- Inheritance and substitution rules are defined (Decision 2; validator §7.2).
- Every kind is covered: material, information, resource.
