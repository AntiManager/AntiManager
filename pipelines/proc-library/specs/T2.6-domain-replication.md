# T2.6 — Domain replication (calibrated method)

Status: draft · Phase 2 · English (service doc)

## Purpose

Replicate the calibrated **Planning** method (T2.1–T2.5) to the remaining
domains so every group reaches the same acceptance: goals + vocabulary-typed I/O
+ closed flow graph + reference economics + a reproducible roll-up. Plan §5:
"replicate to the other groups (production core, logistics, infrastructure)",
**domain by domain, not in parallel**.

## Decision 1 — per-domain pipeline (the calibrated unit)

For a domain file `X.md` the replication runs the same five sub-steps as the
pilot, in order, each with its own gate:

| Sub-step | Pilot analog | Deliverable |
|----------|--------------|-------------|
| 1. Boundaries + shared entities | T2.1 | perimeter sensors/actors + shared `Entity-State` list (vocabulary bump if needed) |
| 2. Subprocesses → operations | T2.2 | every op a `##### Операция` node with `Тип/Цель/Горизонт/Исполнитель/Входы/Выходы/КПЭ/decomposition`, vocabulary refs only |
| 3. Flow graph | T2.3 | per-file «Потоки (Flow Links)» table; axioms §4.2 (no dangling) + §4.5 (cycle with exit) |
| 4. Economics | T2.4 | `Критичность/Периодичность/Трудоёмкость/Стоимость` per op (`author_economics.py`) |
| 5. Roll-up | T2.5 | `rollup.py --scope <domain>` matrix, additive + reproducible |

Gate per domain: **0 errors / 0 warnings** in the domain scope + a green roll-up
row (subprocess → process → group).

## Decision 2 — tranching

A domain may be applied in ordered **tranches** (a process at a time) because
sub-steps 2–3 are the bulk. Each tranche is gated on its own scope
(`0 MISSING GOAL / 0 FREE-TEXT / 0 UNKNOWN TYPE`); dangling (§4.2) stays open
until the domain's flow-link pass (sub-step 3). Structure (node counts) must not
drift: the legacy container synthesis (T0.9) already assigns `CODE-NN` codes in
order, so converted nodes keep the same codes.
