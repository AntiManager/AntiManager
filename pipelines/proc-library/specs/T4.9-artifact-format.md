# T4.9 — Artifact format contract (machine-readable)

Status: frozen · Phase 4 (T4.artifacts) · English (service doc)

Canonical source: umbrella `1791810263662-artifact-chain-ktk-priority-grid.md` §5.
`check_artifacts.py` parses **only** the anchors defined here. Everything else is
ported prose and is deliberately NOT parsed.

## 1. Location

```
<vault>/library/artifacts/
├── Роли.md                              # register doc (artifact: role-register)
├── КТК/<CODE>_КТК.md                    # 10 files      (artifact: ktk)
├── Приоритеты_руководителей.md          # 1 file        (artifact: priority-matrix)
└── Сетка_регулярных_событий.md          # 1 file        (artifact: event-grid)
```

`<CODE>` ∈ the canonical register (T4.0). The checker ignores files whose
frontmatter carries no recognized `artifact:` kind.

## 2. Frontmatter (per artifact)

```yaml
---
artifact: ktk | priority-matrix | event-grid   # required, one of the three
roles: [<КОД>, ...]                            # required: the role codes in this file
---
```

`Роли.md` uses `artifact: role-register` and is not one of the three checked
artifacts (it only carries the register mirror).

## 3. Role section heading (exact)

```
## <Название> (<КОД>)
```

- Heading level **2** (`##`), one space, display name, one space, code in
  parentheses.
- `<КОД>` must be a register code. In КТК each file has exactly one; in the
  priority matrix each role section is one; in the event grid role sections are
  absent (owner lives in the table).

## 4. Table headers (exact strings; cells trimmed; `|`-separated)

**КТК**

```
| № | Код процесса | Роль | keystone | Критический выход | KPI/критерий | Частота контроля | Источник данных | Критичность | Обоснование keystone |
```

**Priority matrix**

```
| Квадрант | Задача | Тип | Делегирование | Профилактика / автоматизация | Связанный процесс (код) |
```

**Event grid**

```
| Триггер/Период | Событие | Длительность | Владелец | Участники | Повестка | Вход | Выход | Процессы | Горизонт |
```

A table is the exact header line, then the `| --- |` separator, then data rows
until the first blank or non-`|` line. Recognized by header equality; extra or
renamed columns fail the exact-match (H-hard).

## 5. Cell vocabularies

- `keystone` ∈ {`да`, `—`}; a plain hyphen/en-dash (`-`/`–`) is accepted as the
  empty marker too (H5). Any other literal fails.
- `Критичность` ∈ {`high`, `medium`, `low`} (H5).
- `Горизонт` ∈ {`shift`, `day`, `week`, `month`, `quarter`, `year`, `event`}
  (H3); must match the enclosing section's cadence (H4; daily→shift/day,
  weekly→week, monthly→month, quarterly→quarter, yearly→year). A grid section
  whose heading matches no cadence word is reported (H4 not applied to it).
- Process codes are matched **literally, case-sensitive**:
  `\b[A-Z][A-Z0-9_-]*-\d{2}(?:-\d{2})*\b`; every reference must resolve to a
  library node (H2). Every row of every artifact must reference **at least one**
  process code — a row with none is a traceability gap (H7). Source-ref tokens
  (`REG-<n>`) are excluded from code matching and flagged by H6 instead.
- Identity/money stop-words are hard (H6), with one exception: a monetary figure
  is allowed when the same line marks it `ориентир` (T4.0 removal list).

## 6. Unparsed content (ported token-free, never asserted)

Prose, `mermaid` blocks, «Интегральные выходы», «Рекомендации», «Содержание»,
«Обоснование keystone» narrative (only its non-emptiness is asserted, W5).

## 7. CLI

```
python pipelines/proc-library/check_artifacts.py "<vault>"
python pipelines/proc-library/check_artifacts.py "<vault>" --cross --semantic
python pipelines/proc-library/check_artifacts.py "<vault>" --json report.json
```

`--cross` adds cross-document warnings (W1/W2/W6); `--semantic` adds the
judgment warnings (W3/W4/W5). Base run performs the hard checks H1–H7.
Exit `0` = no H-violations; `1` = H-violation(s); `2` = usage/IO error.
