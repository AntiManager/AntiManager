# T0.5 — Operation attribute schema & economics roll-up

Status: draft · Phase 0 · English (service doc)

## Purpose

Define the operation data dictionary, typed I/O references, and the economic
roll-up (plan §7, ontology §8).

## Decision 1 — operation data dictionary

| Key | Required | Type / domain | Notes |
|-----|----------|---------------|-------|
| `Тип` | yes | `Simple \| Splitter \| Joiner \| Multiplicator \| Aggregator` | ontology §3 |
| `Цель` | yes | string | T0.4 |
| `Горизонт` | no | `year\|quarter\|month\|week\|shift\|event` | T0.4 |
| `Исполнитель` | yes | role string | role archetype, not a person |
| `Входы` | cond | list of `Entity-State` refs | cond: mandatory unless sensor |
| `Выходы` | cond | list of `Entity-State` refs | cond: mandatory unless actor |
| `КПЭ` | no | string | measurement |
| `Критичность` | no | `high \| medium \| low` | defaults `medium` |
| `Периодичность` | no | `shift\|day\|week\|month\|quarter\|year\|event` + count | frequency |
| `Трудоёмкость` | no | number + `ч` | per single execution |
| `Стоимость` | no | number + `руб` | per execution, **reference rate** |
| `decomposition` | yes | `ATOMIC \| DECOMPOSABLE \| PARTIALLY_DECOMPOSABLE` | T0.6 |
| `Матрица` | cond | `FULL\|DIAGONAL\|CUSTOM` or json | only `Multiplicator` (§4.4) |
| `SOP` | no | link | optional reference |
| `Уровень` | no | `plant` etc. | legacy field, kept if present |

Reference syntax for I/O: `` `Type` `` or `` `Type@State` `` (T0.3). A code-ref
like `PLAN-01-01` is **not** a valid I/O at OPERATION level — it is replaced by
the typed entity (free-text→type conversion, T0.8). At PROCESS/SUBPROCESS the
legacy `Входы (из): PLAN-01-01` code refs stay (they denote the producing node,
not the entity) and are additionally resolved to entities by the flow graph
(Phase 2).

## Decision 2 — roll-up formulas (operation → subprocess → process → domain)

Converge with ontology §8 ("sum for quantities, max for depths, average for
coverage"):

- **Operations count** `N(v) = Σ_{c ∈ children(v)} N(c)`; for an operation
  `N=1`.
- **FTE** `= Σ_i (Трудоёмкость_i × F_i) / AnnualFund`, where `F_i` is the
  number of executions of operation `i` per year (from `Периодичность`), and
  `AnnualFund` = annual working-hours fund (reference constant, §T3.2).
- **Layer cost** `= Σ_i (Стоимость_i × F_i)`.
- **Criticality** `= max(Критичность)` over the subtree (`high > medium > low`).
- **Periodicity** = the highest-frequency cadence present in the subtree.
- **Depth (flow)** per ontology §8 (max path).
- **SOP coverage** = share of operations with `SOP` (average up the tree).

Units: labor `ч`, cost `руб`, FTE dimensionless (person-count). All cost/hours are
**reference values** for an SME template — never client numbers (T3.2).

`F_i` derivation from `Периодичность × count`:

| Периодичность | executions / year (reference) |
|---------------|-------------------------------|
| shift | 3 shifts × 365 (per shift-day) |
| day | 365 |
| week | 52 |
| month | 12 |
| quarter | 4 |
| year | 1 |
| event | set explicitly in `count` |

## Decision 3 — boundary correctness (ontology §4.1)

- Sensor: `|Входы|=0`, `|Выходы|=1`, `isBoundary`.
- Actor: `|Входы|=1`, `|Выходы|=0`, `isBoundary`.
- Any other operation: `|Входы|≥1` and `|Выходы|≥1`.

## Worked example (T0.5 verification target)

```
##### Операция QUAL-03-01-02: Оформление заявки на входной контроль
- **Тип:** `Joiner`
- **Цель:** Сформировать единую заявку на ВК по партии
- **Горизонт:** shift
- **Исполнитель:** Инженер ОТК
- **Входы:** `Сертификат@Есть`, `ДанныеПартии`
- **Выходы:** `Комплект@ЗаявкаНаВК`
- **КПЭ:** 15 мин
- **Критичность:** medium
- **Периодичность:** shift ×3
- **Трудоёмкость:** 0,25 ч
- **Стоимость:** 300 руб
- **decomposition:** ATOMIC
- **SOP:** [СОП-002](sop/QUAL-03-01-02.md)
```

Roll-up check on this single operation: `N=1`; `F=3×365=1095`; FTE `= 0,25 ×
1095 / AnnualFund`; cost `= 300 × 1095`. Formulas reproducible on the control
set.

## Verification

- Data dictionary + formulas defined.
- Formula run on one operation yields finite, reproducible numbers.
