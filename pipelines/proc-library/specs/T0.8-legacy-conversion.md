# T0.8 — Legacy → Spiral A conversion spec

Status: draft · Phase 0 · English (service doc)

## Purpose

Make the transformation from the legacy library (`Proc_library`) into the Spiral
A template **mechanical and repeatable**: "regulation row → operation", "free
text → type", "plant code → node level" (plan T0.8).

## Rule 1 — plant code → node level

| Legacy construct | Node level |
|------------------|------------|
| `# Библиотека …` | LIBRARY |
| `## Группа <CODE>: <name>` | GROUP |
| `### Процесс <CODE>: <name>` | PROCESS |
| `#### Подпроцесс <CODE>: <name>` | SUBPROCESS |
| `##### Операция <CODE>: <name>` **or** `##### Операции подпроцесса <CODE>:` + numbered list | OPERATION |

## Rule 2 — regulation row → operation

A legacy operation is one **top-level numbered item** under `##### Операции
подпроцесса …`. Convert to a `##### Операция …` node:

1. **Code synthesis:** `<subprocess-code>-\{NN\}` where `NN` = the item's ordinal
   (2 digits, 1-based): `QUAL-03-01` + item 1 → `QUAL-03-01-01`.
2. **Name:** the bold lead of the item (`**Проверка сертификатов**`) → heading
   name; the rest becomes the goal/description.
3. **Attributes:** map the nested keys 1:1 — `Исполнитель→Исполнитель`,
   `КПЭ→КПЭ`. `Входы`/`Выходы` are converted by Rule 3 (not copied).
4. **New required attribute:** `Цель` (T0.4) — authored from the item's text
   when absent.
5. **New attributes:** `Тип`, `decomposition` (Rule 5), and optional economics
   (T0.5).

## Rule 3 — free text → type (the semantic core)

Legacy operation I/O is free text (`Входы: План производства; нормы расхода
материалов`). Replace each item with a **vocabulary ref** (T0.3):

1. Split on `;` / `,`.
2. Normalise the phrase; match to the nearest declared `Entity-State` type
   (exact → subtype → supertype). If a state is implied, add `@State`
   (`Сертификаты-Есть` → `Сертификат@Есть`).
3. If no type matches, **do not keep free text**: raise a vocabulary-gap
   candidate `Type?` in the group's conversion log and choose the closest
   existing supertype temporarily; the gap is resolved in a T0.3 version bump.
4. Legacy **code-refs** at PROCESS/SUBPROCESS (`Входы (из): PLAN-01-01`) are
   kept (they denote the producer node) and resolved to entities via the flow
   graph (Phase 2), not rewritten.

## Rule 4 — artifact stripping

Before a file enters the library, remove: dataview inline fields
(`= this.version`, `=dateformat(this.date,…)`), Obsidian escapes (`\[`, `\]`,
`\.`), and leaked Obsidian UI labels (`text`, `Копировать`, `Скачать`). Tabs →
4 spaces. (T0.7 Decision 5.)

## Rule 5 — types & decomposition defaults

- `Тип` is inferred from the I/O cardinality (ontology §3): 1→1 `Simple`,
  1→N `Splitter`, N→1 `Joiner` if the output is `Комплект` else `Aggregator`,
  M→K `Multiplicator`. If unknown → `Simple` pending review.
- `decomposition`: universal operation → `ATOMIC`; plant/technology-specific →
  `DECOMPOSABLE` (T0.6).

## Worked example — convert `QUAL-03-01`

Legacy:

```
##### Операции подпроцесса QUAL-03-01:
1. **Проверка наличия сертификатов**
	- Исполнитель: Кладовщик
		- Входы: Приход-Данные
		- Выходы: Сертификаты-Есть; Сертификаты-Нет
		- КПЭ: 15 мин
```

Converted:

```
##### Операция QUAL-03-01-01: Проверка наличия сертификатов
- **Тип:** `Splitter`
- **Цель:** Установить наличие сертификатов партии
- **Исполнитель:** Кладовщик
- **Входы:** `Документ@Приход`
- **Выходы:** `Сертификат@Есть`, `Сертификат@Нет`
- **КПЭ:** 15 мин
- **decomposition:** ATOMIC
```

Graph validity: types resolve (T0.3); `Splitter` 1→2 (§3); decomposed code follows
Rule 2.

## Verification

- Rules 1–5 are explicit and mechanical.
- Converting `QUAL-03-01` yields a graph node set where every I/O is a vocabulary
  ref and the operation type matches cardinality. Exercised by a T0.9 engine
  test (legacy container form → VALID).
