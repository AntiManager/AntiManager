# T0.7 — Markdown convention (source format)

Status: draft · Phase 0 · English (service doc)

## Purpose

Fix the one Markdown convention that the parser (T0.9, ontology §9.3) and the
authors both follow. Markdown is the single source of truth (ontology §9.1).

## Decision 1 — heading grammar (levels)

| Level | Heading pattern | Example |
|-------|-----------------|---------|
| LIBRARY | `# <title>` | `# Библиотека процессов (шаблон SME)` |
| GROUP | `## Группа <CODE>: <name>` | `## Группа QUAL: Управление качеством продукции` |
| PROCESS | `### Процесс <CODE>: <name>` | `### Процесс QUAL-03: Мониторинг и измерение продукции` |
| SUBPROCESS | `#### Подпроцесс <CODE>: <name>` | `#### Подпроцесс QUAL-03-01: Входной контроль сырья` |
| OPERATION | `##### Операция <CODE>: <name>` | `##### Операция QUAL-03-01-01: Проверка сертификатов` |

Legacy container form is also accepted by the parser for the pre-refactor files:
`##### Операции подпроцесса <CODE>:` heading followed by a **numbered list** of
operations (see Decision 3).

`<CODE>` matches `^[A-Z][A-Z0-9_]*(-[0-9]{2})+$` (e.g. `SL_PLAN-01-02`,
`QUAL-03-01-01`). Codes are never translated, renumbered or re-prefixed.

## Decision 2 — attribute syntax

- **GROUP / PROCESS / SUBPROCESS block** — consecutive lines, each
  `**Key:** value` (legacy italic `*Key:*` is accepted and normalised):

  ```
  **Код:** QUAL-03
  **Владелец:** Директор по качеству
  **Триггер:** Поступление партии …
  **Цель:** Подтверждённое соответствие партии
  **КПЭ:** Доля забракованных партий ≤ …
  **Горизонт:** month
  **APQC:** 4.3.3
  **Входы (из):** QUAL-03-00; внешний (поставщик)
  **Выходы (в):** QUAL-05-01
  ```

  Trailing two-space line breaks are tolerated; the block ends at the first
  blank line or non-matching line. **Leading blank lines between the heading and
  the block are skipped** (the layout every split group file uses); only a blank
  line *inside* the block terminates it. Applied in T1.2 (engine `_collect_attr_block`).

- **OPERATION attributes** — bullet list `- **Key:** value` immediately under
  the operation heading (T0.5 dictionary). I/O values are `` `Type` `` /
  `` `Type@State` `` refs, comma- or semicolon-separated.

## Decision 3 — legacy operation container (accepted)

```
##### Операции подпроцесса QUAL-03-01:

1. **Проверка наличия сертификатов**
	- Исполнитель: Кладовщик
		- Входы: Приход-Данные
		- Выходы: Сертификаты-Есть; Сертификаты-Нет
		- КПЭ: 15 мин
```

The parser treats each top-level numbered item as one operation; nested
`- Исполнитель/Входы/Выходы/КПЭ` are its attributes. Codes are synthesised as
`<subprocess-code>-NN` (documented in T0.8).

## Decision 4 — flow links

A flow-link table per file (or per group), ontology §12:

```
| Источник (Операция.Выход) | → | Приёмник (Операция.Вход) | Условие |
|---------------------------|:---:|---------------------------|---------|
| QUAL-03-01-01.Сертификаты-Есть | → | QUAL-03-01-02.Сертификаты-Есть | … |
```

## Decision 5 — diagrams and artifacts

- ```` ```mermaid ```` blocks are **non-authoritative** (documentation only); the
  parser ignores them for the graph (the graph is built from links/tables).
- **Forbidden (Obsidian/data artifacts):** dataview inline `= this.version`,
  `=dateformat(...)`, and escape artifacts `\[`, `\]`, `\.`. These must be
  stripped before a file enters the library (T0.8 step 4).
- Frontmatter is optional; if present it carries `tags`, `status`, `updated`,
  and `vocabulary` (T0.3 version this file validates against).

## Decision 6 — file layout

```
library/
  INDEX.md          # LIBRARY node (H1) + group registry + mermaid overview
  QUAL.md           # one file per GROUP (## Группа …)
  MFG.md
  SL_PLAN.md
  …
  technologies/     # externalised MFG tech processes (existing precedent)
```

Parsing is **folder-scoped**: the parser unions every `library/*.md` (recursing
into `technologies/`), taking the LIBRARY node from `INDEX.md` when present.
